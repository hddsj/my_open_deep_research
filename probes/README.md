# probes

探针（probe）不是测试。

- **测试**断言"应该是什么"，跑在 CI 里，红了就是有问题。
- **探针**测量"实际是什么"，手动跑，输出的是**数字和事实**，本身不判断对错。

探针存在的理由：**在拿一个工具下结论之前，先确认这个工具能分辨你关心的差别。**
这里每个脚本都对应一个当时无法靠读代码或读文档回答的问题，答案直接影响了后续的
设计决策 —— 有两次结论和事前的猜测相反。

全部脚本都不需要 API key、不联网。检索类探针需要 `knowledge_base/` 下有 PDF 且
索引已建立（首次约 30 分钟）；图接线类探针不依赖本项目，几秒跑完。

```bash
uv run python probes/<name>.py
```

## 检索链路

### `probe_score_scales.py`

对比两路召回的分数量纲，并量化 parent 块对 BM25 召回名额的挤占。

**背景**：向量路在 `search()` 里有 `where={"type": "child"}` 过滤，BM25 路没有 ——
parent 与 child 一起参与打分，直到融合阶段才被跳过。两路召回口径不一致。

**输出**：两路的分数区间、量级比、未过滤 top-k 里 parent 占几个（全库基准 19.2%）、
凑满 k 个 child 需要扫描多少条。

### `probe_fusion_diff.py`

RRF 与「逐 query min-max 归一化 + 加权」两种融合方式，结果到底差多少。

**思路**：**先测差异，再测优劣。** 如果两者的 top-5 几乎重合，就没有必要为
"谁更好"去建一个带人工标注的评测集。这个脚本不需要任何标注。

**输出**：top-5 / top-10 重合数、第一名是否相同、共同候选的平均名次位移。

## 图接线（LangGraph `Command` 路由）

这四个探针回答的是同一类问题：`Command(goto=...)` 路由与图的**声明**之间有哪些
不一致，以及这些不一致能不能被观测到。结论直接决定了
`tests/test_graph_wiring.py` 的设计。

### `probe_command_vs_edge.py`

节点返回 `Command(goto=...)` 时，同时声明的静态边还会不会生效？

**结论**：会。即使节点 `return Command(goto=END)`，静态边的目标依然执行 ——
图不会终止。同时也测了两者指向同一节点时目标跑几次（答案：一次，不是两次）。

### `probe_graph_reachability.py`

`get_graph()` 是靠遍历收集边的吗？没有返回标注的 `Command` 节点会截断链条吗？

**结论**：会。`get_graph()` 从 `START` 做可达性遍历，把没有标注的 `Command` 节点
当成死胡同接到 `END` 并停止 —— **其下游的显式 `add_edge` 也一并消失**。

### `probe_incomplete_literal.py`

`Literal` 里漏列一个 `goto` 目标会怎样？

**结论**：运行时完全不受影响，照样跳到没声明的目标。但图里会画出一条**永远走不到
的假边**，同时**隐藏真实路径**。所以标注写不全比不写更危险 —— 不写的图明显是断的，
写不全的图看起来完整可信。

### `probe_dedup.py`

静态边与 `Command` 边指向同一目标时，`get_graph()` 显示成几条边？

**结论**：一条，且 `conditional=True` —— **与"只有标注"的情况输出完全相同**。
也就是说，**从编译后的图无法判断静态边是否存在**。

这个结论推翻了原本的测试设计：在 `get_graph()` 上断言"出边恰好两条"抓不到
"静态边被加回来"这个回归，那样的断言永远不会红。因此
`tests/test_graph_wiring.py` 的静态边断言改读 `builder.edges`，其余读
`get_graph()` —— 两个数据源各自对另一类缺陷是隐形的。
